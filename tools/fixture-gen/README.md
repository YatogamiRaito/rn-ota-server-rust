# Fixture generation

The parity fixtures under `tests/fixtures/` are recorded from the **real** npm packages, not
hand-written. That is what makes the parity claim testable: `tests/decision_tests.rs` and
`tests/semver_parity_tests.rs` replay them against the Rust implementation.

| Fixture                                | Generated by                           | Records                                                                    |
| -------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------- |
| `tests/fixtures/decision_fixtures.json` | `tests/generate_decision_fixtures.mjs` | `@hot-updater/js` `getUpdateInfo` decisions (appVersion + fingerprint)      |
| `tests/fixtures/semver_fixtures.json`   | `tests/generate_semver_fixtures.mjs`   | `@hot-updater/plugin-core` `semverSatisfies` + npm `semver` `coerce` output |

`tests/fixtures.json` (cohort/hash vectors) is checked in as static data and has no generator.

## Running the generators

The generators import the upstream packages, so they need a `node_modules` that resolves them.
This directory exists to provide one:

```bash
cd tools/fixture-gen && npm install && cd ../..
```

Then run the generators from the repository root with `NODE_PATH` pointed at that install:

```bash
NODE_PATH=tools/fixture-gen/node_modules \
  node tests/generate_decision_fixtures.mjs > tests/fixtures/decision_fixtures.json

NODE_PATH=tools/fixture-gen/node_modules \
  node tests/generate_semver_fixtures.mjs   > tests/fixtures/semver_fixtures.json
```

## When to regenerate

Only when upgrading the upstream hot-updater version. Then:

```bash
git diff --stat tests/fixtures/
```

- **Empty diff** — upstream behavior did not change; nothing to do.
- **Formatting-only diff** — leave the files alone.
- **Semantic diff** (an `expected` value changed) — upstream changed its behavior. Do not "fix"
  the fixtures: update the Rust implementation until `cargo test` is green again, and record the
  change in `docs/upstream-parity.md`.

## Pinning

`package.json` here pins the upstream version the fixtures were recorded from. Bump it deliberately
as part of an upgrade, never incidentally.
